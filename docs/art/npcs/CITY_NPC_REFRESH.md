## Cohesive body design

Use roughly six-head proportions, soft anime faces with **rounded natural chins**, coherent human jaws, clear wrists and broad matte painted fabric blocks. Avoid needle chins, skull spikes, armor, saturated neon, photoreal hair/fur, dense ornaments, crushed blacks and baked lighting. Thai identity comes from chong kraben, pha sin/sabai, cloth sashes, selective hems and existing headwear/tools. Six masters receive distinct new Meshy bodies; they are not copies of current player GLBs.

Canonical body height is **1.72 m for adults and 1.20 m for the novice**, measured from grounded soles to anatomical crown, excluding external headwear, after all runtime scales. If existing `look.scale` remains, compensate during normalization rather than multiply the target twice. Do not import the player's CombatView scale into NPC normalization. The novice retains NPC ID/name/occupation; the authorized change is its youthful visual body and height.

Each preview specifies a neutral A-pose with arms clear of torso, level coherent shoulders, forward separated feet and open, unobscured palms. Each hand must have four fingers plus one correctly placed thumb. Inspect source palms and thumb sides with actual close cameras. Do not approve five digits from a tiny thumbnail or from texture markings. Check shoulder/armpit continuity, elbows, neck, crotch/skirt bridges, knees and ankles before binding. Cloth must leave room for existing seated prayer/chant and work poses; do not solve a bad source by hiding it with a prop.

The keeper's actual request omitted that model field; do not invent a resolved version or retroactively add CLI flags to its history. The target polycount is a request, not an actual triangle-count measurement.

Refine: `mode=refine`, the **successful preview task ID of that same family**, `enable_pbr=false`, `texture_resolution=2k`, `remove_lighting=true`, `target_formats=[glb]`. Replace placeholder IDs with real task IDs before submitting. Use the CLI's `--data` JSON input and common flags `--async --output-schema v1 --format json --no-update-check`.

Rigging follows an independently reviewed textured source, through `--input-task-id` and `--height-meters 1.72` (`1.2` for novice). Approximately 24 humanoid bones is the parent's informational expectation; actual counts/names remain unknown until delivery, and are not a fixed acceptance requirement. Resolve actual delivered bones for sockets; no bone name or rig success is claimed here. These are anatomical semantics, not invented exported bone names. Tools in `src/npc/body/gearParts.js` are authored in procedural frame space. A hand-bone adapter needs a calibrated attachment transform; do not apply the old forearm-space offset directly to a wrist. Verify actual grip surfaces, tool direction and rigid attachment in the relevant work states. Shared female bodies must not inherit the supplier basket on every market seller. No new presumed pestle or held-bowl animation is included.

Proposed module boundaries for parent integration: an explicit ID registry in `src/npc/NPCModels.js` and a model/resource/state/socket adapter in `src/npc/NPCModelRenderer.js`, using the JSON's proposed `public/models/npcs/{family}.glb` paths. These modules and paths are **planned**, not implemented or populated here. Preserve `NPCManager` schedule/nav/talk/visibility ownership, and retain `NPCRenderer` instancing for background citizens. Selected models must not render duplicate procedural body/clothing/headwear parts. Existing fixed-length frame matrices need a rest-pose adapter, not direct copying onto Meshy bones or substitution of player clips.

Shared geometry/textures may be cached, but rigs and mutable appearance variants need independent instance ownership. Unload instance/skeleton resources without disposing shared resources still in use. Preserve map filtering, ground origin, interaction range and service identity.
